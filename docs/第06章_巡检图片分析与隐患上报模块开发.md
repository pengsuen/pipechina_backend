# 第6章 巡检图片分析与隐患上报

[文档导航](README.md) · [上一章：异常调查与工单](第05章_异常分级与维检工单模块开发.md) · [下一章：报告](第07章_生产运行日报与事件复盘模块开发.md)

## 6.1 定位与边界

巡检模块将图片转换为待人工复核的隐患候选，再关联生产事件或启动事件调查。视觉模型不负责自动批准工单，也不替代人工确认。

图片通过StorageProvider保存；本地文件系统和S3是可配置实现，不应把“仅保存本地”写成代码强制的数据驻留保证。VisionProvider通过配置的HTTP服务推理；网络是否出域取决于实际部署、地址和访问控制。

业务规则位于app/modules/inspection；视觉服务源码位于services/vision，容器部署位于infra/compose/project.yml。容器隔离重型依赖，不意味着视觉服务变成第三方中间件。部署步骤统一见 [infra](../infra/README.md)。

## 6.3 完整处理链路

```text
创建巡检 → 创建图片元数据和上传授权 → 上传字节 → complete 校验
→ 创建分析 Job → Outbox → vision Worker → 保存候选
→ 人工确认/驳回 → 关联已有事件，或创建事件并进入第5章调查
```

1. 创建巡检时按组织和调用者数据范围授权。
2. 创建图片记录时由后端生成安全对象键。原始文件名仅作元数据，不能拼接成任意文件系统路径。
3. 客户端使用上传授权：S3可直传；本地实现通过受保护的存储接口传输。
4. complete验证服务端实际对象信息和摘要，不能只相信客户端的SHA-256。
5. 只有verified且未删除的图片进入分析。
6. 模型输出先保存为候选；确认之后才允许下游关联或调查。

上传授权成功不等于字节已经上传，更不等于文件已经通过验证。排障时分别查看上传记录、图片状态、对象是否存在和Job状态。

## 6.4 分析任务与模型调用

analyze_inspection() 查询可用图片，创建inspection_image_analysis类型任务，使用vision队列。build_runtime_snapshot() 固定模型/提示词等运行配置；基础快照包含image_count，不能因此宣称已固化全部图片内容。

异步模式返回Job ID；内联模式直接调用同一业务执行函数，主要便于测试。execute_inspection_analysis() 检查终态和取消标记，使用任务对应的Provider逐图调用inspect()，结合站场、管线和设备文本生成上下文，保存候选与结果。

这是结构化视觉推理，不是ReAct Agent，也没有必要加入多个视觉角色。图像推理的输入、输出和服务契约以 [ports](../app/ports) 与services/vision为准。

当前巡检任务没有套用知识模块的公共执行租约。已有状态检查不能等价描述为任意并发下exactly-once；重复投递和取消效果应按实际任务检查点验收。

## 6.5 人工复核与事件衔接

- 确认/驳回作用于隐患候选；模型建议并不自动成为正式生产结论。
- `link_finding_to_event()`检查隐患已确认，并校验巡检及目标事件的数据权限后建立关联。该方法未覆盖完整的业务去重和跨组织一致性约束。
- start_finding_workflow() 为已确认隐患创建新的已确认生产事件及版本，建立关联，再调用事件分类流程；不是单纯把已有事件ID传给工单模块。
- 启动调查还需要满足事件分类权限。调查结果仍需人工审核，工单也有独立状态机。
- 不应无条件重复调用启动工作流接口；通用HTTP幂等键只能覆盖相应请求，不代表业务天然禁止重复建事件。

本模块没有自动把所有图片和隐患同步为知识库文档。需要知识入库时应走第8章明确的版本、审核和发布流程。

## 6.7 联调与验证

先完成第1章的API、IdP、存储、Worker和Beat启动；Worker需要消费vision，Outbox发布和平台维护还需要maintenance。只启动vision Worker而没有Outbox发布机制，会出现接口返回成功但任务不执行。

联调依次检查：上传 → complete → 分析Job → 候选 → 人工复核 → 事件关联 → 调查 → 工单审核。可先用Fake Provider验证业务，再用真实视觉服务验证模型协议、内存、超时及网络边界。

数据库测试必须先配置可丢弃的独立TEST_DATABASE_URL；测试会重建public schema。确认后运行：

```bash
uv run pytest tests/test_inspection_flow.py tests/test_media_security.py tests/test_provider_contracts.py -q
```

这些测试不等于真实模型效果评测。上线前还要覆盖超大/损坏图片、越权读取、上传未完成、重复分析、模型超时、对象存储不可用及取消检查点。不要将文档验收清单当作已经执行的测试结果。
