# 第 6 章 巡检图片分析与隐患上报模块开发

## 6.1 本章目标

本章完成巡检记录、图片上传、本地视觉分析、隐患人工复核和隐患关联事件的完整后端流程。

完成后，系统能够：

1. 创建站场巡检记录；
2. 将人工上传的图片保存到本地对象目录；
3. 校验图片类型、大小和上传结果；
4. 通过统一视觉接口调用本地视觉推理服务；
5. 把识别结果保存为待复核隐患；
6. 由授权人员确认或驳回隐患；
7. 将已确认隐患关联到生产运行事件并启动后续处置流程。

本模块坚持两个安全边界：图片文件默认不离开本地环境；模型识别结果只能作为辅助信息，未经人工确认不得自动生成生产结论。

## 6.2 明确处理链路

巡检图片采用异步处理链路：

```text
创建巡检记录
  -> 申请图片上传地址
  -> 上传图片到本地对象目录
  -> 完成上传并校验
  -> 创建视觉分析任务
  -> vision 队列执行本地模型推理
  -> 保存待复核隐患
  -> 人工确认或驳回
  -> 关联生产事件或发起处置流程
```

本地存储负责文件生命周期，PostgreSQL 只保存对象键、文件元数据、分析结果和审计信息。这样既避免在数据库中保存大对象，也便于以后把 `StorageProvider` 切换为 AWS S3。

## 6.4 设计数据模型

在 `app/modules/inspection/domain/models.py` 中建立四个实体。

### 6.4.1 巡检记录

`InspectionRecord` 保存巡检业务上下文：

```python
class InspectionRecord(UUIDPrimaryKeyMixin, TimestampMixin, Base):
    __tablename__ = "inspection_records"

    organization_unit_id: Mapped[UUID] = mapped_column(Uuid(as_uuid=True), nullable=False)
    station_name: Mapped[str] = mapped_column(String(200), nullable=False)
    pipeline_name: Mapped[str | None] = mapped_column(String(200))
    equipment_name: Mapped[str | None] = mapped_column(String(200))
    inspected_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), nullable=False)
    notes: Mapped[str | None] = mapped_column(Text)
    status: Mapped[str] = mapped_column(String(32), default="draft", nullable=False)
    created_by: Mapped[UUID] = mapped_column(Uuid(as_uuid=True), nullable=False)
```

### 6.4.2 巡检图片

`InspectionImage` 保存图片元数据，不保存图片二进制：

```python
class InspectionImage(UUIDPrimaryKeyMixin, TimestampMixin, Base):
    __tablename__ = "inspection_images"

    inspection_id: Mapped[UUID] = mapped_column(
        Uuid(as_uuid=True), ForeignKey("inspection_records.id", ondelete="RESTRICT")
    )
    object_key: Mapped[str] = mapped_column(String(1024), unique=True, nullable=False)
    filename: Mapped[str] = mapped_column(String(255), nullable=False)
    mime_type: Mapped[str] = mapped_column(String(120), nullable=False)
    size_bytes: Mapped[int] = mapped_column(Integer, nullable=False)
    status: Mapped[str] = mapped_column(String(32), default="pending", nullable=False)
    deleted: Mapped[bool] = mapped_column(Boolean, default=False, nullable=False)
    protected_reason: Mapped[str | None] = mapped_column(String(300))
```

图片状态按以下顺序变化：

```text
pending -> verified -> analyzing -> analyzed
```

逻辑删除使用 `deleted`、`deleted_by` 和 `deleted_at`，避免破坏审计链。已被确认隐患引用的图片应设置保护原因，不允许直接删除。

### 6.4.3 隐患发现

`InspectionFinding` 保存视觉模型给出的候选结果：

```python
class InspectionFinding(UUIDPrimaryKeyMixin, TimestampMixin, Base):
    __tablename__ = "inspection_findings"

    inspection_id: Mapped[UUID] = mapped_column(
        Uuid(as_uuid=True), ForeignKey("inspection_records.id", ondelete="RESTRICT")
    )
    image_id: Mapped[UUID] = mapped_column(
        Uuid(as_uuid=True), ForeignKey("inspection_images.id", ondelete="RESTRICT")
    )
    title: Mapped[str] = mapped_column(String(300), nullable=False)
    category: Mapped[str] = mapped_column(String(80), nullable=False)
    severity: Mapped[str] = mapped_column(String(20), nullable=False)
    description: Mapped[str] = mapped_column(Text, nullable=False)
    evidence: Mapped[str] = mapped_column(Text, nullable=False)
    confidence: Mapped[float] = mapped_column(nullable=False)
    review_status: Mapped[str] = mapped_column(String(32), default="pending", nullable=False)
    reviewed_by: Mapped[UUID | None] = mapped_column(Uuid(as_uuid=True))
    review_reason: Mapped[str | None] = mapped_column(Text)
```

`confidence` 只用于辅助排序，不直接决定隐患是否成立。`review_status` 仅允许 `pending`、`confirmed` 或 `rejected`。

### 6.4.4 隐患关联

`InspectionFindingLink` 保存隐患与事件之间的可撤销关联：

```python
class InspectionFindingLink(UUIDPrimaryKeyMixin, TimestampMixin, Base):
    __tablename__ = "inspection_finding_links"

    finding_id: Mapped[UUID] = mapped_column(
        Uuid(as_uuid=True), ForeignKey("inspection_findings.id", ondelete="RESTRICT")
    )
    target_type: Mapped[str] = mapped_column(String(40), nullable=False)
    target_id: Mapped[UUID] = mapped_column(Uuid(as_uuid=True), nullable=False)
    active: Mapped[bool] = mapped_column(Boolean, default=True, nullable=False)
    created_by: Mapped[UUID] = mapped_column(Uuid(as_uuid=True), nullable=False)
```

关联采用独立表而不是把事件编号直接写入隐患表，便于保留创建、撤销和审计历史。

## 6.6 实现 Repository

在 `infrastructure/repository.py` 中集中保存常用查询：

```python
class InspectionRepository:
    def __init__(self, session: AsyncSession) -> None:
        self.session = session

    async def get_inspection(self, inspection_id: UUID) -> InspectionRecord | None:
        return await self.session.get(InspectionRecord, inspection_id)

    async def get_finding(self, finding_id: UUID) -> InspectionFinding | None:
        return await self.session.get(InspectionFinding, finding_id)
```

列表查询必须增加组织范围条件，不能先查出全部数据再在 Python 中过滤。

## 6.7 创建巡检记录

在 `application/service.py` 中创建记录并写入审计日志：

```python
async def create_inspection(
    session: AsyncSession,
    payload: InspectionCreate,
    user: CurrentUser,
) -> InspectionRecord:
    row = InspectionRecord(
        organization_unit_id=user.organization_unit_id,
        station_name=payload.station_name,
        pipeline_name=payload.pipeline_name,
        equipment_name=payload.equipment_name,
        inspected_at=payload.inspected_at,
        notes=payload.notes,
        status="draft",
        created_by=user.user_id,
    )
    session.add(row)
    await session.flush()
    await add_audit(
        session,
        user=user,
        action="inspection.create",
        resource_type="inspection",
        resource_id=row.id,
    )
    await session.commit()
    return row
```

## 6.8 建立图片上传流程

图片上传分为“申请上传”和“确认完成”两个接口。后端在第一步写入待上传记录并生成 `UploadGrant`，客户端把文件写入存储提供者，最后由后端核验对象大小和校验值。

对象键采用以下格式：

```text
inspections/{inspection_id}/{image_id}/{safe_filename}
```

创建上传会话时执行三项检查：

1. `size_bytes` 不得超过 `MAX_IMAGE_BYTES`；
2. MIME 类型必须属于 `image/jpeg`、`image/png`、`image/webp`；
3. 当前用户必须拥有该巡检记录所在组织的数据权限。

完成上传时使用 `StorageProvider.head()` 读取真实元数据。声明大小与实际大小不一致时返回 `409 Conflict`，图片状态不得进入 `verified`。

## 6.9 定义视觉模型抽象

在 `app/ports/vision.py` 中定义协议：

```python
class VisionProvider(Protocol):
    name: str
    model: str

    async def inspect(
        self,
        media: MediaRef,
        *,
        context: str,
    ) -> list[VisionFinding]: ...
```

业务模块只依赖 `VisionProvider`。当前默认实现通过 HTTP 调用本地视觉服务，后续可以替换为自训练模型或其他远程服务，无需修改巡检业务代码。

本地视觉服务可选用 MiniCPM-V 4.6 作为起始实现。生产部署时，模型服务应位于受控内网，通过只读对象访问或流式输入读取图片。千问文本模型不参与图片上传和图片推理。

环境变量配置示例：

```dotenv
VISION_PROVIDER=local_http
VISION_BASE_URL=http://127.0.0.1:8102
VISION_MODEL=openbmb/MiniCPM-V-4.6
STORAGE_PROVIDER=local_filesystem
LOCAL_STORAGE_ROOT=./data/objects
```

## 6.10 创建异步分析任务

调用 `POST /inspections/{inspection_id}:analyze` 时先验证至少存在一张 `verified` 图片，然后创建 `AIJob`：

```python
job = await create_job(
    session,
    user=user,
    job_type="inspection_image_analysis",
    resource_type="inspection",
    resource_id=inspection.id,
    task_name="app.modules.inspection.analyze_inspection",
    queue="vision",
    config_snapshot={
        "provider": provider.name,
        "model": provider.model,
        "prompt_version": "inspection_findings.v1",
        "image_count": len(images),
    },
    enqueue=True,
)
```

任务快照必须记录提供者、模型、提示词版本和图片数量，以便复现分析条件。

在 `application/tasks.py` 中注册 Celery 任务：

```python
@celery_app.task(
    name="app.modules.inspection.analyze_inspection",
    acks_late=True,
)
def analyze_inspection_task(job_id: str) -> dict[str, str]:
    return {"job_id": job_id, "status": asyncio.run(_analyze(job_id))}
```

把任务路由到 `vision` 队列。视觉 Worker 可以独立配置 GPU、内存和并发数，不占用文本任务 Worker。

## 6.11 保存模型候选结果

任务执行时逐张分析图片：

```python
for image in images:
    image.status = "analyzing"
    candidates = await provider.inspect(
        MediaRef(
            object_key=image.object_key,
            mime_type=image.mime_type,
            size_bytes=image.size_bytes,
            filename=image.filename,
        ),
        context=context,
    )
    for candidate in candidates:
        session.add(
            InspectionFinding(
                inspection_id=inspection.id,
                image_id=image.id,
                title=candidate.title,
                category=candidate.category,
                severity=candidate.severity,
                description=candidate.description,
                evidence=candidate.evidence,
                confidence=candidate.confidence,
                review_status="pending",
            )
        )
    image.status = "analyzed"
```

处理完成后，把巡检状态更新为 `review_pending`，把任务状态更新为 `succeeded`。某张图片失败时，应记录错误并让任务进入可重试状态；不能把未完成结果标记为成功。

## 6.12 实现人工复核

确认和驳回接口使用同一个复核服务。服务必须校验当前状态为 `pending`，保存复核人、理由和审计日志。

```text
pending -> confirmed
pending -> rejected
```

已确认或已驳回结果不得重复复核。确需纠正时，应由具有管理权限的业务流程创建新的复核记录，不直接覆盖历史审计字段。

## 6.13 关联生产事件

只有 `confirmed` 隐患允许关联生产事件。关联前完成以下检查：

1. 隐患存在且属于当前用户的数据范围；
2. 生产事件存在且属于相同可访问组织范围；
3. 相同的有效关联不存在；
4. 创建人和创建时间写入关联记录；
5. 操作写入审计日志。

撤销关联时将 `active` 置为 `false`，同时保存撤销人、时间和原因，不物理删除记录。

## 6.14 注册 API

在 `api/router.py` 中注册以下接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/inspections` | 创建巡检记录 |
| `GET` | `/inspections` | 查询巡检列表 |
| `GET` | `/inspections/{inspection_id}` | 查询巡检、图片和隐患 |
| `POST` | `/inspections/{inspection_id}/images` | 申请图片上传 |
| `POST` | `/inspections/{inspection_id}/images/{image_id}:complete` | 完成上传校验 |
| `DELETE` | `/inspections/{inspection_id}/images/{image_id}` | 逻辑删除图片 |
| `POST` | `/inspections/{inspection_id}:analyze` | 创建视觉分析任务 |
| `POST` | `/findings/{finding_id}:confirm` | 确认隐患 |
| `POST` | `/findings/{finding_id}:reject` | 驳回隐患 |
| `POST` | `/findings/{finding_id}:link-event` | 关联生产事件 |
| `GET` | `/findings/{finding_id}/links` | 查询有效关联 |
| `DELETE` | `/findings/{finding_id}/links/{link_id}` | 撤销关联 |
| `POST` | `/findings/{finding_id}:start-workflow` | 启动处置流程 |

所有列表和详情接口都必须应用组织数据范围。上传、分析、复核、关联和撤销操作都要记录审计日志。

## 6.16 手工联调顺序

先启动基础服务、API、视觉服务和视觉 Worker：

```bash
docker start postgres rabbitmq redis
docker compose --profile local-models up -d --build vision
uv run uvicorn app.main:app --reload --port 8000
uv run celery -A app.bootstrap.celery_app:celery_app worker -Q vision -l INFO
```

在 Swagger UI 中按以下顺序操作：

1. 创建巡检记录；
2. 为巡检记录申请图片上传；
3. 使用返回的上传地址写入 JPEG、PNG 或 WebP 文件；
4. 调用完成上传接口；
5. 创建分析任务；
6. 查询任务进度，等待状态变为 `succeeded`；
7. 查询巡检详情，检查图片和待复核隐患；
8. 确认一条隐患并驳回另一条；
9. 将已确认隐患关联到生产事件；
10. 查询关联记录并验证审计日志。

检查本地文件位置：

```bash
find data/objects/inspections -type f -maxdepth 5
```

确认图片保存在本地对象目录，视觉服务可以读取对象，千问文本接口的调用日志中不包含图片内容。
