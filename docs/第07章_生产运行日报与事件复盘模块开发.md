# 第 7 章 生产运行日报与事件复盘模块开发

## 7.1 本章目标

本章完成生产运行日报和事件复盘的来源汇集、分段生成、版本管理、人工审核、发布、撤回和文件导出，并完成整个后端项目的集成验证。

完成后，系统能够：

1. 按组织、日期、站场和管线范围创建报告；
2. 只采集已确认的交接记录、生产事件、工单和巡检隐患；
3. 使用 LangGraph 编排 Map-Reduce 报告生成流程；
4. 通过千问文本模型生成报告草稿；
5. 保存每次人工编辑和恢复形成的版本；
6. 执行提交审核、批准、驳回、发布和撤回；
7. 导出可下载的报告文件；
8. 由 Celery Beat 幂等地创建每日运行报告；
9. 完成全量测试、构建和发布标签。

## 7.2 明确报告边界

报告生成遵循“确认数据进入、草稿结果输出、人工审核发布”的原则：

```text
已确认业务记录
  -> 按报告范围查询来源
  -> 每 20 条切分一组
  -> 千问生成各组草稿
  -> 程序确定性合并
  -> 保存新版本
  -> 人工编辑与审核
  -> 发布或驳回
  -> 导出归档
```

模型不得直接查询数据库，也不得把未确认记录当作正式事实。报告中的来源编号、待核实事项和模型配置必须可追踪。

## 7.4 设计数据模型

在 `domain/models.py` 中建立报告、版本、来源和导出实体。

### 7.4.1 报告主表

`OperationReport` 保存业务日期、范围、当前版本和发布版本：

```python
class OperationReport(UUIDPrimaryKeyMixin, TimestampMixin, Base):
    __tablename__ = "operation_reports"

    organization_unit_id: Mapped[UUID] = mapped_column(Uuid(as_uuid=True), nullable=False)
    report_type: Mapped[str] = mapped_column(String(32), nullable=False)
    business_date: Mapped[date] = mapped_column(Date, nullable=False)
    timezone: Mapped[str] = mapped_column(String(64), nullable=False)
    scope_filter: Mapped[dict] = mapped_column(JSON, default=dict, nullable=False)
    scope_digest: Mapped[str] = mapped_column(String(64), nullable=False)
    status: Mapped[str] = mapped_column(String(32), default="draft", nullable=False)
    current_version_id: Mapped[UUID | None] = mapped_column(Uuid(as_uuid=True))
    published_version_id: Mapped[UUID | None] = mapped_column(Uuid(as_uuid=True))
    created_by: Mapped[UUID] = mapped_column(Uuid(as_uuid=True), nullable=False)
```

`scope_digest` 是规范化范围的摘要。组织、报告类型、业务日期和范围摘要应建立唯一约束，防止定时任务重复创建同一份日报。

### 7.4.2 报告版本

`ReportVersion` 保存不可覆盖的内容快照：

```python
class ReportVersion(UUIDPrimaryKeyMixin, TimestampMixin, Base):
    __tablename__ = "report_versions"

    report_id: Mapped[UUID] = mapped_column(
        Uuid(as_uuid=True), ForeignKey("operation_reports.id", ondelete="RESTRICT")
    )
    version: Mapped[int] = mapped_column(Integer, nullable=False)
    source: Mapped[str] = mapped_column(String(32), nullable=False)
    title: Mapped[str] = mapped_column(String(300), nullable=False)
    content: Mapped[dict] = mapped_column(JSON, nullable=False)
    review_status: Mapped[str] = mapped_column(String(32), default="draft", nullable=False)
    immutable: Mapped[bool] = mapped_column(Boolean, default=False, nullable=False)
```

每次模型生成、人工编辑或版本恢复都新增版本。已发布版本设置 `immutable=True`，禁止覆盖。

### 7.4.3 来源快照

`ReportSource` 保存报告版本采用的业务来源：

```python
class ReportSource(UUIDPrimaryKeyMixin, TimestampMixin, Base):
    __tablename__ = "report_sources"

    report_version_id: Mapped[UUID] = mapped_column(
        Uuid(as_uuid=True), ForeignKey("report_versions.id", ondelete="RESTRICT")
    )
    source_type: Mapped[str] = mapped_column(String(64), nullable=False)
    source_id: Mapped[UUID] = mapped_column(Uuid(as_uuid=True), nullable=False)
    source_snapshot: Mapped[dict] = mapped_column(JSON, nullable=False)
```

来源快照用于解释报告生成时看到的事实，避免业务记录后续变化导致历史报告无法复核。

### 7.4.4 导出任务

`ReportExport` 保存格式、状态和对象键。导出文件仍通过 `StorageProvider` 管理，当前写入本地目录，后期可以切换到 S3。

## 7.6 规范化报告范围

先对范围字段排序、去除空值并生成稳定摘要：

```python
def digest_scope(scope: dict[str, str]) -> str:
    normalized = json.dumps(scope, ensure_ascii=False, sort_keys=True, separators=(",", ":"))
    return hashlib.sha256(normalized.encode("utf-8")).hexdigest()
```

创建报告时检查唯一性：

```text
organization_unit_id + report_type + business_date + scope_digest
```

重复请求应返回已有报告或明确的冲突响应，不能产生两份相同日报。

## 7.7 汇集已确认来源

在 `application/service.py` 中实现 `_collect_sources()`。查询必须同时满足组织范围、业务日期、报告范围和确认状态。

来源规则如下：

| 来源类型 | 纳入条件 | 内容来源 |
|---|---|---|
| 交接班记录 | 已确认 | 当前确认版本及交接重点 |
| 生产运行事件 | 已确认 | 当前事件版本和证据摘要 |
| 维检工单 | 已进入有效执行或闭环状态 | 工单标题、等级和处理结果 |
| 巡检隐患 | 已确认 | 隐患描述、证据和等级 |

统一转换为小型字典：

```python
{
    "id": str(source.id),
    "type": "production_event",
    "title": source.title,
    "severity": source.severity,
    "content": source.description,
}
```

只传递生成报告所需字段，避免把用户信息、审计日志、文件路径和无关业务字段发送给文本模型。

## 7.9 使用 LangGraph 编排 Map-Reduce

当来源很多时，一次调用模型会增加上下文长度、超时和遗漏风险。Map-Reduce 先把来源切分为小组，分别生成草稿，再由程序合并。

在 `application/workflow.py` 中定义状态：

```python
class ReportState(TypedDict, total=False):
    source_items: list[dict[str, Any]]
    chunks: list[list[dict[str, Any]]]
    partials: list[dict[str, Any]]
    result: dict[str, Any]
```

切分函数每组最多 20 条：

```python
def partition(state: ReportState) -> ReportState:
    items = state.get("source_items", [])
    chunks = [items[index : index + 20] for index in range(0, len(items), 20)] or [[]]
    return {"chunks": chunks}
```

建立图：

```python
def build_report_graph():
    builder = StateGraph(ReportState)
    builder.add_node("partition", partition)
    builder.add_node("map", map_deterministic)
    builder.add_node("reduce", reduce_deterministic)
    builder.add_edge(START, "partition")
    builder.add_edge("partition", "map")
    builder.add_edge("map", "reduce")
    builder.add_edge("reduce", END)
    return builder.compile()
```

LangGraph 负责步骤顺序和状态传递。模型调用发生在切分完成后，最终来源编号由程序确定性合并，减少模型遗漏或虚构编号的风险。

## 7.10 调用千问生成分段草稿

对每个来源分组调用 `TextLLMProvider.generate_structured()`：

```python
draft = await provider.generate_structured(
    operation="report_generation",
    system_prompt=(
        "你是油气管网生产运行报告助手。只能使用输入中的已确认来源生成草稿，"
        "不得补造事实；所有采用的来源必须出现在 source_ids，疑点放入 pending_facts。"
    ),
    user_prompt=json.dumps(
        {"report_type": report_type, "sources": chunk},
        ensure_ascii=False,
    ),
    response_model=ReportDraft,
)
```

当前默认文本提供者为千问远程 API：

```dotenv
TEXT_PROVIDER=qwen
DASHSCOPE_API_KEY=填写百炼API-Key
QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_TEXT_MODEL=qwen3.7-plus
```

这里传给千问的是筛选后的结构化文本，不包含本地音频和图片文件。业务代码依赖 `TextLLMProvider`，后期可以切换到 OpenAI 或企业自建文本模型。

## 7.11 确定性合并草稿

多个分段草稿采用程序合并，不让模型自由改写来源编号：

```python
headings = {heading for draft in drafts for heading in draft.sections}
sections = {
    heading: "\n".join(draft.sections[heading] for draft in drafts if draft.sections.get(heading))
    for heading in sorted(headings)
}
pending_facts = list(dict.fromkeys(fact for draft in drafts for fact in draft.pending_facts))
```

合并完成后创建新的 `ReportVersion`，保存所有来源快照，把报告状态置为 `draft`，并把当前版本编号写回报告主表。

## 7.13 实现版本管理

人工修改报告时不更新旧版本，而是执行以下步骤：

1. 校验当前版本不是不可变版本；
2. 查询当前最大版本号并加一；
3. 新建 `source="manual"` 的版本；
4. 复制必要的来源关系；
5. 更新 `current_version_id`；
6. 写入编辑审计日志。

恢复历史版本也采用“复制为新版本”，不把主表指针直接指向旧快照。这样可以完整说明版本变化顺序。

## 7.14 实现审核和发布状态

报告状态按以下路径流转：

```text
draft -> pending_review -> approved -> published -> withdrawn
                         -> rejected -> draft（修改后形成新版本）
```

规则如下：

- 只有 `draft` 版本可以提交审核；
- 只有 `pending_review` 版本可以批准或驳回；
- 只有 `approved` 版本可以发布；
- 发布时把版本设置为不可变，并写入 `published_version_id`；
- 只有 `published` 报告可以撤回；
- 撤回必须填写原因，历史发布版本仍保留。

审核与发布接口必须检查相应权限，并写入操作者、理由和前后状态。

## 7.15 创建 DOCX 导出

导出采用异步任务。创建 `ReportExport` 后，把任务发送到 `report` 队列；Worker 使用报告的已发布版本生成 DOCX，再通过 `StorageProvider` 保存。

对象键示例：

```text
reports/{report_id}/exports/{export_id}/operation-report.docx
```

导出完成后保存对象键和状态。下载接口通过 `StorageProvider.signed_download_url()` 返回短时有效地址。本地存储实现可以返回受保护的内部下载路由；S3 实现可以返回预签名 URL。

## 7.16 建立日报定时任务

在 Celery Beat 中增加日报任务：

```python
beat_schedule = {
    "generate-daily-operation-reports": {
        "task": "app.modules.report.generate_daily_reports",
        "schedule": crontab(hour=16, minute=10),
    },
}
```

这里的 Worker 使用 UTC，`16:10 UTC` 对应次日 `00:10 Asia/Shanghai`。业务日期必须通过 `ZoneInfo("Asia/Shanghai")` 计算，不能直接使用服务器本地时区。

定时任务遍历启用的组织单元，并通过唯一范围摘要检查当日记录是否存在。重复触发时跳过已有报告，保证幂等。
