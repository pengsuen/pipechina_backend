[文档导航](README.md) · [上一章：公共基座](第02章_公共基座搭建启动与测试.md) · [下一章](第04章_生产运行事件抽取与归档模块开发.md)

本章按现有代码讲解，目录和实体已经存在。业务入口是`app/modules/handover/`，独立ASR源码是`services/asr/`，部署入口是`infra/compose/project.yml`。文件可用本地私有存储或S3，不限定必须上传到外部对象存储。

## 3.1 本章目标

```text
创建音频记录
  -> 获得签名上传地址
  -> 上传到配置的对象存储
  -> 完成上传并校验大小/哈希
  -> 创建异步转写任务
  -> 通过统一 ASR Provider 转写
  -> 保存转写版本和分段
  -> 人工校订
  -> 通过统一文字模型 Provider 生成结构化交接重点
  -> 人工确认
```

**本节文件：** 先通读`app/modules/handover/`，再对照`app/ports/speech.py`、`app/ports/text.py`、`app/ports/storage.py`理解三个外部能力边界。

### 3.1.1 本章先理解的概念

| 概念 | 含义 | 本模块中的作用 |
|---|---|---|
| 主记录 | 表示同一个业务对象当前处于什么状态 | `AudioRecord`、`ManualOperationRecord`保存当前版本指针和业务状态 |
| 版本记录 | 每次修改都新增一行，而不是覆盖历史正文 | 转写、摘要和人工记录均可追溯到旧版本 |
| 两阶段上传 | 先创建资源和上传授权，再通知服务端校验上传结果 | S3可直传；本地存储仍经过专用签名传输路由，不应宣称所有上传都绕过API进程 |
| 异步任务 | API只创建`AsyncJob`并返回，Worker稍后执行耗时处理 | 转写和摘要不会阻塞HTTP请求 |
| 候选结果 | 模型输出不是最终业务事实 | 转写和摘要需要人工确认或校订后才能进入后续业务 |

本章中的`tasks.py`是Celery对业务执行方法的后台入口，不保存业务规则。RabbitMQ负责传递任务消息，Worker调用Task，Task再恢复数据库和Provider资源并进入Service。

## 3.3 设计数据模型

`domain/models.py`中已有以下实体：

| 实体 | 主要用途 |
|---|---|
| `AudioRecord` | 录音主记录、上传状态和当前版本指针 |
| `AudioTranscriptVersion` | 每次机器转写或人工校订形成的不可覆盖版本 |
| `AudioTranscriptSegment` | 带开始/结束毫秒的分段文本 |
| `HandoverSummaryVersion` | 交接重点版本及其来源转写版本 |
| `ManualOperationRecord` | 无录音场景下的人工运行记录 |
| `ManualOperationRecordVersion` | 人工记录的版本历史 |

所有实体都继承`UUIDPrimaryKeyMixin`和`TimestampMixin`，因此默认带有以下公共列：

### 3.3.1 `AudioRecord`：录音主记录

对应数据表`audio_records`，保存录音的业务归属、存储信息、处理状态以及当前版本指针。

| 列 | 类型 | 是否可空 | 含义 |
|---|---|---|---|
| `organization_unit_id` | UUID | 否 | 录音所属组织单元，关联`organization_units.id` |
| `shift_date` | date | 否 | 交接班所属日期 |
| `shift_code` | string(40) | 否 | 班次编码，如早班、夜班或业务自定义编码 |
| `filename` | string(255) | 否 | 用户上传时的原始文件名 |
| `object_key` | string(1024) | 否 | 对象存储中的唯一对象键 |
| `mime_type` | string(120) | 否 | 录音文件的MIME类型 |
| `size_bytes` | integer | 否 | 文件大小，单位为字节，必须大于0 |
| `duration_ms` | integer | 是 | 音频时长，单位为毫秒；获取前可为空 |
| `language` | string(20) | 是 | 转写使用的语言标识，如`zh-CN` |
| `upload_status` | string(32) | 否 | 上传状态：`pending`、`verified`或`failed` |
| `business_status` | string(32) | 否 | 业务状态，本模块做到哪个部分了：`draft`、`transcribed`、`summary_ready`或`confirmed` |

对应数据表`audio_transcript_versions`，每次机器转写或人工校订都新增一条版本。

| 列 | 类型 | 是否可空 | 含义 |

## 3.4 定义请求与响应模型

`domain/schemas.py`中的模型用于校验接口请求和组织响应数据，不直接对应数据库表。请求模型约束客户端可以提交什么，响应模型约束接口向客户端返回什么。

### 3.4.1 `AudioRecordCreate`：创建录音请求

用于创建录音主记录并申请上传授权。

| 属性 | 类型 | 是否必填 | 作用 |
|---|---|---|---|
| `shift_date` | date | 是 | 指定录音所属的交接班日期 |
| `shift_code` | string | 是 | 指定班次编码，长度为1～40个字符 |
| `organization_unit_id` | UUID | 否 | 指定录音所属组织；省略时使用当前用户所属组织 |
| `filename` | string | 是 | 保存用户上传时的原始文件名，长度为1～255个字符 |
| `size_bytes` | integer | 是 | 声明音频文件大小，单位为字节，必须大于0 |
| `mime_type` | string | 是 | 声明音频MIME类型，长度为3～120个字符 |
| `sha256` | string | 否 | 客户端计算的SHA-256十六进制摘要，必须为64个字符，用于上传完成后的完整性比对 |

### 3.4.2 `UploadComplete`：完成上传请求

用于通知服务端对象已经上传完毕，并触发存储侧元数据校验。

| 属性 | 类型 | 是否必填 | 作用 |
|---|---|---|---|
| `server_sha256` | string | 否 | 调用方在完成阶段上报的SHA-256摘要，必须为64位十六进制字符串；它只用于与对象存储返回的可信摘要交叉比对 |

### 3.4.3 `TranscriptSegmentInput`：人工转写分段输入

表示人工校订转写中的一个时间轴分段。

| 属性 | 类型 | 是否必填 | 作用 |
|---|---|---|---|
| `start_ms` | integer | 是 | 分段开始时间，单位为毫秒，必须大于或等于0 |
| `end_ms` | integer | 是 | 分段结束时间，单位为毫秒，必须大于0且大于`start_ms` |
| `text` | string | 是 | 该时间段对应的转写文字，不允许为空 |
| `speaker_label` | string | 否 | 可选的说话人标识，用于区分不同发言人 |

### 3.4.4 `TranscriptUpdate`：人工校订转写请求

用于提交一份完整的人工校订版本，而不是覆盖已有机器转写。

| 属性 | 类型 | 是否必填 | 作用 |
|---|---|---|---|
| `full_text` | string | 是 | 校订后的完整转写文本，不允许为空 |
| `segments` | list[`TranscriptSegmentInput`] | 否 | 校订后的时间轴分段，默认是空列表；存在多个分段时必须按时间排序且不能重叠 |

分段是否超过录音总时长无法只靠请求模型判断，因此由Service结合`AudioRecord.duration_ms`继续校验。

### 3.4.5 `SummaryUpdate`：人工摘要请求

用于创建一个人工交接摘要版本，并明确摘要所依据的转写及证据分段。

| 属性 | 类型 | 是否必填 | 作用 |
|---|---|---|---|
| `content` | `HandoverSummary` | 是 | 保存严格结构化的交接摘要，包括运行状态、待办、风险和注意事项 |
| `transcript_version_id` | UUID | 否 | 指定摘要依据的转写版本；省略时使用录音的当前转写版本 |
| `source_segment_ids` | list[UUID] | 否 | 指定摘要引用的证据分段，列表内不允许重复；省略时引用目标转写的全部分段 |

| 属性 | 类型 | 作用 |
|---|---|---|

| `pending_items` | list[string] | 记录需要后续处理的待办事项 |
| `risks` | list[string] | 记录已经识别的风险 |

## 3.5 实现Repository

Repository只负责持久化查询，不调用模型、不判断HTTP权限。典型接口：

```python
class HandoverRepository:
    def __init__(self, session: AsyncSession) -> None:
        self.session = session

    async def get_audio(self, audio_id: UUID) -> AudioRecord | None:
        return await self.session.get(AudioRecord, audio_id)

    async def list_segments(self, version_id: UUID) -> list[AudioTranscriptSegment]:
        result = await self.session.scalars(
            select(AudioTranscriptSegment)
            .where(AudioTranscriptSegment.transcript_version_id == version_id)
            .order_by(AudioTranscriptSegment.segment_index)
        )
        return list(result)
```

查询必须带组织数据范围，接口层读取对象后仍需执行`require_data_scope()`。

Repository本身不接收`CurrentUser`。列表接口在SQL语句中使用`data_scope_clause()`，避免先查出越权数据；单条资源由Service或Router使用`require_data_scope()`再校验。当前Repository收敛了录音与分段查询，复杂业务状态转换仍留在Service。

## 3.6 Service层方法详解

Service层负责权限与数据范围校验、业务状态转换、事务控制、版本管理以及Provider调用编排。Repository只处理持久化查询，Router只处理HTTP输入输出和少量尚未下沉的接口业务。

### 3.6.1 查询与锁定辅助方法

#### `get_audio()`

- **功能：** 按ID查询未删除的录音主记录。找不到记录或记录已逻辑删除时抛出`NotFoundError`。
- **重要参数：** `session`是异步数据库会话；`audio_id`是录音主记录UUID。
- **返回：** `AudioRecord`。此方法只保证记录存在且未删除，不负责权限校验，调用者仍需执行`require_data_scope()`。

#### `list_current_segments()`

- **功能：** 查询录音当前转写版本的全部分段，并按`segment_index`排序；录音尚无当前转写时直接返回空列表。
- **重要参数：** `session`；`audio`，其中`current_transcript_version_id`决定查询哪个版本。
- **返回：** `list[AudioTranscriptSegment]`。

#### `_lock_audio()`

- **功能：** 使用`SELECT ... FOR UPDATE`锁定指定录音，串行化同一录音的版本写入和状态变更，避免并发生成重复版本号或覆盖当前指针。
- **重要参数：** `audio_id`；`include_deleted`默认为`False`，仅后台任务收尾等需要识别“执行期间被删除”状态的场景传`True`。
- **返回：** 被锁定的`AudioRecord`；记录不存在或不允许读取已删除记录时抛出`NotFoundError`。

#### `_transcript_for_audio()`

- **功能：** 同时按录音ID和转写版本ID查询版本，保证该版本确实属于指定录音，防止跨录音引用转写。
- **重要参数：** `audio_id`、`transcript_id`。
- **返回：** `AudioTranscriptVersion`；归属关系不成立时抛出`ConflictError`。

### 3.6.2 音频创建与上传校验

#### `create_audio()`

- **功能：** 创建`AudioRecord`和配套的`UploadSession`，生成安全对象键，向`StorageProvider`申请上传授权，记录授权过期时间和审计日志，最后提交事务。它是两阶段上传的第一阶段，不接收音频文件本身。
- **重要参数：** `payload`提供班次、组织、文件名、大小、MIME和可选SHA-256；`user`用于组织范围和`HANDOVER_CREATE`权限校验；`storage`用于生成上传地址；`settings`提供最大文件大小和MIME白名单。省略`organization_unit_id`时使用当前用户所属组织。
- **返回：** `AudioCreateResponse`，包含录音视图、上传会话ID、对象键、上传URL和必须随上传携带的请求头。
- **关键规则：** 文件名经过`safe_object_filename()`清理；超出大小限制返回413，不在MIME白名单中返回415；数据库记录和上传授权成功后统一提交。

#### `complete_upload()`

- **功能：** 完成两阶段上传的第二阶段。锁定录音，检查上传会话存在、未过期且仍为`pending`，再通过`storage.head()`核验对象大小、MIME和可信校验和。通过后把上传会话和录音的上传状态都改为`verified`，并写审计日志。
- **重要参数：** `audio`是待确认的录音；`user`必须具有`HANDOVER_PROCESS`权限和对应数据范围；`storage`用于读取已保存对象的元数据；`server_sha256`是调用方再次上报的摘要，只用于与存储侧可信摘要交叉比对。
- **返回：** `None`。方法只修改当前事务中的实体，不自行`commit`，由调用它的Router统一提交。
- **关键规则：** 客户端声明的哈希不能充当可信事实；若创建时声明了SHA-256，而存储后端不能提供可信SHA-256，则拒绝验证。大小、MIME或摘要不一致均抛出冲突错误，不能进入转写流程。

### 3.6.3 转写任务与转写版本

#### `transcribe_audio()`

- **功能：** 校验录音可转写后创建`audio_transcription`异步任务和运行时配置快照。异步模式通过事务发件箱投递到`audio`队列；内联模式创建同样的Job后立即调用`execute_transcription()`，保证测试和生产共用状态模型。
- **重要参数：** `audio`；`user`，需要`HANDOVER_PROCESS`权限；`provider`，用于生成Provider配置快照并在内联模式执行；`inline`决定立即执行还是写入Outbox。
- **返回：** `UUID`类型的Job ID，供前端查询进度。
- **关键规则：** 只有`upload_status=verified`且尚未确认的录音可创建转写任务；非内联模式会在返回前提交任务和Outbox。

#### `execute_transcription()`

- **功能：** 执行一个已经持久化的转写任务。它先把Job更新为`running`并提交，再调用ASR Provider；随后校验分段顺序、重叠和音频时长，重新锁定Job与录音并复查取消、删除和确认状态，最终创建机器转写版本及全部分段，更新当前转写指针和录音元数据。
- **重要参数：** `job`是持久化任务；`audio`是目标录音；`user`记入新版本的创建人；`provider`是默认ASR Provider，实际执行时会结合Job快照解析出对应Provider。Provider接收`MediaRef`、热词和语言。
- **返回：** `None`。成功、失败和取消状态均写回Job；Provider异常在记录失败信息并提交后继续抛出。
- **关键规则：** 已处于终态的Job重投时直接返回，保证成功后的重复投递不会产生新版本；耗时外部调用期间不持有数据库事务；新转写会清空当前摘要指针，因为旧摘要引用的是旧转写。

#### `update_transcript()`

- **功能：** 保存人工校订结果。锁定录音后创建`source=manual`的新转写版本和分段，不覆盖机器版本或旧人工版本；随后更新当前转写指针、清空当前摘要并写审计日志。
- **重要参数：** `audio`；`payload.full_text`是完整校订文本，`payload.segments`是按时间顺序的分段；`user`需要`HANDOVER_EDIT`权限。
- **返回：** 新创建的`AudioTranscriptVersion`。
- **关键规则：** 已确认录音不可修改；若已知`audio.duration_ms`，任何分段都不得超过音频总时长；版本号取当前最大值加一，并依靠行锁和数据库唯一约束共同防止并发冲突。

### 3.6.4 摘要任务与摘要版本

本模块的摘要生成不是Agent。它不会自主选择工具或规划步骤，而是对一个确定的转写版本执行一次受约束的`generate_structured()`调用，并用`HandoverSummary`校验四类固定字段：运行状态、待办事项、风险和注意事项。Celery Worker只是可靠执行任务，也不是Agent。

#### `summarize_audio()`

- **功能：** 为当前转写创建`handover_summary`异步任务，将转写版本ID、提示词和模型配置写入运行时快照。异步模式投递到`ai_text`队列，内联模式立即调用`execute_summary()`。
- **重要参数：** `audio`；`user`，需要`HANDOVER_PROCESS`权限；`provider`是文字模型Provider；`inline`控制执行方式。
- **返回：** `UUID`类型的Job ID。
- **关键规则：** 必须已有当前转写，且录音不能已经确认；快照固定本次任务引用的转写版本，防止重试时悄悄改用新版本。

#### `execute_summary()`

- **功能：** 执行持久化摘要任务。方法先将Job置为`running`并提交，再调用文字Provider生成严格结构化摘要；模型返回后重新锁定Job和录音，检查取消、删除、确认以及转写是否已经变化，收集当前转写的全部分段ID，调用`_save_summary()`保存AI摘要版本。
- **重要参数：** `job`；`audio`；`transcript`是任务创建时确定的转写版本；`user`是版本创建人；`provider`会按Job快照解析。提示词由`system_prompt()`和`render_user_prompt()`从快照构造。
- **返回：** `None`。成功时Job进度更新为100；Provider异常会记录失败状态并重新抛出；转写过期等业务竞争会把Job标为失败或取消后返回。
- **关键规则：** 如果当前转写已不再等于任务快照中的版本，则以`STALE_TRANSCRIPT_VERSION`失败，禁止把基于旧文本生成的摘要设为当前摘要。

#### `_save_summary()`

- **功能：** 统一保存AI或人工摘要版本，计算下一个版本号，写入摘要内容及证据分段，并更新录音的当前摘要指针和状态。
- **重要参数：** `transcript_version_id`指明摘要依据；`content`是已经通过结构校验的摘要字典；`source_segment_ids`是证据分段；`source`取`ai`或`manual`；`user`是创建人。
- **返回：** 新创建的`HandoverSummaryVersion`。
- **关键规则：** 本方法只`flush`，不提交事务，也不单独做权限或归属校验；调用者必须先锁定录音并完成校验。

#### `update_summary()`

- **功能：** 创建人工摘要版本。它验证引用的转写属于当前录音，并验证显式提供的证据分段全部属于该转写；未提供分段ID时自动引用该转写的全部分段。保存后写审计日志并提交。
- **重要参数：** `payload.content`是严格类型的`HandoverSummary`；`payload.transcript_version_id`可选，省略时使用当前转写；`payload.source_segment_ids`可选；`user`需要`HANDOVER_EDIT`权限。
- **返回：** 新创建的`HandoverSummaryVersion`。
- **关键规则：** 已确认录音不可编辑；摘要必须引用一个有效转写，且不得引用其他转写或其他录音的分段。

### 3.6.5 人工运行记录

#### `create_manual_record()`

- **功能：** 在没有录音的场景下创建人工运行记录及其第1个版本，设置当前版本指针并直接把业务状态设为`confirmed`，然后记录审计并提交。
- **重要参数：** `payload`提供组织、发生时间、记录类型、正文和结构化补充数据；`user`需要`HANDOVER_CREATE`权限。组织省略时使用用户所属组织，发生时间统一转换为UTC ISO 8601字符串。
- **返回：** 新创建的`ManualOperationRecord`，可通过`current_version_id`找到首个版本。

#### `update_manual_record()`

- **功能：** 锁定人工记录，创建下一个不可覆盖的版本，更新`current_version_id`，写审计日志并提交。
- **重要参数：** `record_id`是人工记录UUID；`payload.content`和`payload.structured_data`构成新版本；`user`需要目标组织内的`HANDOVER_EDIT`权限。
- **返回：** 更新当前版本指针后的`ManualOperationRecord`。
- **关键规则：** 找不到记录时抛出`NotFoundError`；版本号取当前最大值加一，旧版本继续保留用于历史追溯。

### 3.6.6 Service之外的确认与删除

人工确认和删除目前由`app/modules/handover/api/router.py`的`post_confirm()`与`delete_audio()`实现，因此不列入Service方法：

- 确认前检查当前转写和当前摘要都存在，并验证当前摘要确实引用当前转写；确认后设置`business_status=confirmed`。
- 已确认录音不能重复确认、修改或删除；未确认录音通过`deleted=true`逻辑删除，保留版本和审计历史。
- 这两段业务目前位于Router。若将业务逻辑下沉至Service，需同步调整接口实现和本节说明。

## 3.7 Task后台任务入口详解

`app/modules/handover/application/tasks.py`是Celery Worker与Service层之间的适配层。接口创建异步Job后，事务发件箱把任务投递给Celery；Task根据Job ID重建数据库、用户和Provider上下文，再调用Service中真正的业务执行方法。Task不负责生成转写或摘要，也不直接写业务版本。

整体调用关系如下：

```text
API 创建 AsyncJob 和 TaskOutbox
  -> Outbox 发布 Celery 消息
  -> Celery Task 接收 job_id
  -> 异步 process_* 方法加载运行资源
  -> Service execute_* 方法执行业务
  -> 返回 Job 最终状态
```

### 3.7.1 `process_transcription()`：执行转写后台任务

- **功能：** 根据Job ID加载Worker运行资源、数据库会话、异步任务和录音记录，恢复任务创建人的用户上下文，然后调用Service的`execute_transcription()`完成ASR转写及版本保存。
- **重要参数：** `job_id`是字符串形式的异步任务UUID；`settings`是可选配置，测试时可以显式传入，生产执行时省略并使用Worker默认配置。
- **返回：** `str`类型的Job状态，例如`succeeded`、`failed`或`cancelled`。
- **执行资源：** `worker_resources()`提供数据库和ASR Provider；`job_user()`根据`requested_by`重新读取当前账号、组织与有效授权，检查任务权限，不是复用请求时的静态权限集合。
- **异常处理：** `execute_transcription()`抛出异常时，调用`mark_job_failed()`记录失败状态和错误信息，然后继续抛出异常，让Celery感知本次执行失败。

### 3.7.2 `process_summary()`：执行摘要后台任务

- **功能：** 根据Job ID加载Job和录音，并从`job.config_snapshot["transcript_version_id"]`恢复任务创建时固定的转写版本；确认该版本存在且属于目标录音后，调用Service的`execute_summary()`生成并保存结构化摘要。
- **重要参数：** `job_id`是字符串形式的异步任务UUID；`settings`用于可选地覆盖Worker配置。
- **返回：** `str`类型的Job最终状态。
- **执行资源：** `worker_resources()`提供数据库和文字模型Provider；传给Service的`transcript`来自任务快照，而不是执行时临时读取当前转写，因此能够识别任务排队期间发生的版本变化。
- **异常处理：** 摘要执行异常时调用`mark_job_failed()`并重新抛出。若快照中的转写版本不存在或不属于该录音，方法直接抛出`ValueError`，防止错误证据进入摘要流程。

### 3.7.3 `transcribe_audio_task()`：Celery转写入口

- **功能：** 注册名为`app.modules.handover.transcribe_audio`的同步Celery任务，并通过`asyncio.run()`启动异步的`process_transcription()`。
- **重要参数：** `job_id`，由Outbox发布器随Celery消息传入。
- **返回：** `dict[str, str]`，包含原始`job_id`和处理后的`status`，便于在Celery结果中识别任务及其状态。
- **关键配置：** `acks_late=True`表示Worker执行结束后才确认消息；如果进程在执行中异常退出，消息可以重新投递。Service会检查Job终态，因此成功任务被重复投递时不会再次创建业务版本。

### 3.7.4 `summarize_audio_task()`：Celery摘要入口

- **功能：** 注册名为`app.modules.handover.summarize_audio`的同步Celery任务，并通过`asyncio.run()`调用异步的`process_summary()`。
- **重要参数：** `job_id`，对应已经持久化的摘要Job。
- **返回：** `dict[str, str]`，包含`job_id`和Job最终`status`。
- **关键配置：** 同样启用`acks_late=True`；可靠重投由Celery负责，是否已经完成、是否取消以及转写版本是否过期由Service根据数据库状态判断。

交接班模块提供：

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/v1/audio-records` | 创建音频和上传授权 |

列表接口在SQL层使用`data_scope_clause()`，默认最多返回最近100条；单条接口再做对象级数据范围校验。版本接口返回版本内容和证据关系，而不是只返回版本号，否则前端无法展示历史差异或完成审计追溯。
