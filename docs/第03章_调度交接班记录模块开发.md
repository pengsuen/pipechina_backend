# 第 3 章 调度交接班记录模块开发

## 3.1 本章目标

本章实现交接班录音从创建到确认的完整闭环：

```text
创建音频记录
  -> 获得签名上传地址
  -> 上传本地文件存储
  -> 完成上传并校验大小/哈希
  -> 创建异步转写任务
  -> 本地 faster-whisper 转写
  -> 保存转写版本和分段
  -> 人工校订
  -> 千问生成结构化交接重点
  -> 人工确认
```

录音文件不发送给千问。千问只接收已经转写的文字，用于提炼运行状态、待办、风险和注意事项。

## 3.3 设计数据模型

在 `domain/models.py` 中建立以下实体：

| 实体 | 主要用途 |
|---|---|
| `AudioRecord` | 录音主记录、上传状态和当前版本指针 |
| `AudioTranscriptVersion` | 每次机器转写或人工校订形成的不可覆盖版本 |
| `AudioTranscriptSegment` | 带开始/结束毫秒的分段文本 |
| `HandoverSummaryVersion` | 交接重点版本及其来源转写版本 |
| `ManualOperationRecord` | 无录音场景下的人工运行记录 |
| `ManualOperationRecordVersion` | 人工记录的版本历史 |

`AudioRecord` 的关键字段：

```python
class AudioRecord(UUIDPrimaryKeyMixin, TimestampMixin, Base):
    __tablename__ = "audio_records"

    organization_unit_id: Mapped[UUID]
    shift_date: Mapped[date]
    shift_code: Mapped[str]
    filename: Mapped[str]
    object_key: Mapped[str]
    mime_type: Mapped[str]
    size_bytes: Mapped[int]
    duration_ms: Mapped[int | None]
    language: Mapped[str | None]
    upload_status: Mapped[str]
    business_status: Mapped[str]
    current_transcript_version_id: Mapped[UUID | None]
    current_summary_version_id: Mapped[UUID | None]
    confirmed_by: Mapped[UUID | None]
    deleted: Mapped[bool]
    created_by: Mapped[UUID]
```

版本表不能原地覆盖历史内容。人工校订时新增版本并更新主记录的当前版本指针。

## 3.4 定义请求与响应模型

在 `domain/schemas.py` 中创建：

```python
class AudioRecordCreate(BaseModel):
    shift_date: date
    shift_code: str = Field(min_length=1, max_length=40)
    organization_unit_id: UUID | None = None
    filename: str = Field(min_length=1, max_length=255)
    size_bytes: int = Field(gt=0)
    mime_type: str = Field(min_length=3, max_length=120)
    sha256: str | None = Field(default=None, pattern=r"^[0-9a-fA-F]{64}$")


class TranscriptSegmentInput(BaseModel):
    start_ms: int = Field(ge=0)
    end_ms: int = Field(gt=0)
    text: str = Field(min_length=1)
    speaker_label: str | None = None


class TranscriptUpdate(BaseModel):
    full_text: str = Field(min_length=1)
    segments: list[TranscriptSegmentInput]
```

必须校验相邻分段顺序、`end_ms > start_ms`、分段文本非空以及分段范围不超过音频时长。

## 3.5 实现 Repository

Repository 只负责持久化查询，不调用模型、不判断 HTTP 权限。典型接口：

```python
class HandoverRepository:
    def __init__(self, session: AsyncSession) -> None:
        self.session = session

    async def get_audio(self, audio_id: UUID) -> AudioRecord | None:
        return await self.session.get(AudioRecord, audio_id)

    async def list_segments(self, version_id: UUID) -> list[AudioTranscriptSegment]:
        result = await self.session.scalars(
            select(AudioTranscriptSegment)
            .where(AudioTranscriptSegment.transcript_version_id == version_id)
            .order_by(AudioTranscriptSegment.segment_index)
        )
        return list(result)
```

查询必须带组织数据范围，接口层读取对象后仍需执行 `require_data_scope()`。

## 3.6 创建音频记录和上传授权

创建记录时先写入主表和 `upload_sessions`，再由 `StorageProvider` 生成上传授权：

```python
async def create_audio(
    session: AsyncSession,
    *,
    payload: AudioRecordCreate,
    user: CurrentUser,
    storage: StorageProvider,
    settings: Settings,
) -> AudioCreateResponse:
    org_id = payload.organization_unit_id or user.organization_unit_id
    require_data_scope(user, org_id)
    if payload.size_bytes > settings.max_audio_bytes:
        raise AppError("FILE_TOO_LARGE", "audio exceeds configured size limit", 413)
    safe_name = safe_object_filename(payload.filename)
    audio = AudioRecord(
        organization_unit_id=org_id,
        shift_date=payload.shift_date,
        shift_code=payload.shift_code,
        filename=payload.filename,
        object_key="pending",
        mime_type=payload.mime_type,
        size_bytes=payload.size_bytes,
        upload_status="pending",
        business_status="draft",
        created_by=user.user_id,
    )
    session.add(audio)
    await session.flush()
    audio.object_key = f"handover/{org_id}/{audio.id}/{safe_name}"
    upload = UploadSession(
        resource_type="audio_record",
        resource_id=audio.id,
        organization_unit_id=org_id,
        object_key=audio.object_key,
        filename=audio.filename,
        mime_type=audio.mime_type,
        size_bytes=audio.size_bytes,
        client_sha256=payload.sha256,
        status="pending",
    )
    session.add(upload)
    grant = await storage.create_upload(
        object_key=audio.object_key,
        mime_type=audio.mime_type,
        size_bytes=audio.size_bytes,
    )
    await session.commit()
    return AudioCreateResponse(
        audio=AudioRecordView.model_validate(audio),
        upload_session_id=upload.id,
        object_key=grant.object_key,
        upload_url=grant.upload_url,
        upload_headers=grant.headers,
    )
```

两阶段上传把大文件传输和业务接口事务分开。第一阶段创建资源和授权，第二阶段在 `/uploads:complete` 中确认对象确实存在且元数据一致。

## 3.7 完成上传校验

完成上传时执行：

1. 查询音频和上传会话；
2. 校验上传会话仍为 `pending`；
3. 调用 `storage.head(object_key)`；
4. 比较声明大小和实际大小；
5. 保存调用方提供的服务端摘要，未提供时使用存储元数据摘要；
6. 更新 `upload_sessions.status=verified`；
7. 更新 `audio_records.upload_status=verified`；
8. 写入审计日志。

发现大小不一致时返回 409，不能进入转写队列。本地签名上传路由还会校验请求 `Content-Type` 与授权时的 MIME 是否一致。

## 3.8 创建转写任务

`POST /audio-records/{audio_id}:transcribe` 不直接执行模型，而是在同一事务内创建：

- `ai_jobs`：`job_type=audio_transcription`；
- `task_outbox`：任务名 `app.modules.handover.transcribe_audio`，队列 `audio`；
- 配置快照：ASR provider、模型、语言和热词版本。

接口返回 202 和 Job ID。前端通过 `/api/v1/jobs/{job_id}` 或 SSE 查询进度。

## 3.9 执行本地 ASR

Worker 加载 Job、AudioRecord 和当前 ProviderBundle：

```python
media = MediaRef(
    object_key=audio.object_key,
    mime_type=audio.mime_type,
    size_bytes=audio.size_bytes,
    filename=audio.filename,
)
result = await providers.asr.transcribe(
    media,
    hotwords=hotwords,
    language="zh",
)
```

`HTTPASRProvider` 使用 `StorageProvider.materialize()` 获得临时本地路径，再以 multipart 请求本地 `/v1/transcriptions`。业务模块不知道文件位于磁盘还是 S3。

ASR 返回统一结构：

```json
{
  "language": "zh",
  "duration_ms": 83000,
  "full_text": "站场运行平稳，二号阀门需要复查。",
  "segments": [
    {
      "index": 0,
      "start_ms": 0,
      "end_ms": 4200,
      "text": "站场运行平稳。",
      "speaker_label": null,
      "confidence": null
    }
  ],
  "provider_request_id": "..."
}
```

保存时创建新的 `AudioTranscriptVersion` 和全部分段，更新主记录当前版本指针，并将 `business_status` 设为 `transcribed`。

## 3.10 支持人工校订

`PUT /audio-records/{audio_id}/transcript` 必须创建 `source=manual` 的新版本。校订后的文本成为后续摘要和事件抽取的来源，机器版本继续保留。

版本号由数据库当前最大版本加一。写入前必须锁定主记录或通过唯一约束防止并发生成相同版本号。

## 3.11 生成交接重点

在 `app/ports/models.py` 中定义严格结构：

```python
class HandoverSummary(StrictProviderOutput):
    operating_status: list[str]
    pending_items: list[str]
    risks: list[str]
    attention_items: list[str]
```

调用文字端口：

```python
summary = await provider.generate_structured(
    operation="handover_summary",
    system_prompt=(
        "你是油气管网交接班记录整理助手。只能依据输入转写文本归纳，"
        "不得补造设备状态、数值、结论或处理结果。"
    ),
    user_prompt=transcript.full_text,
    response_model=HandoverSummary,
)
```

把结构化结果转成稳定的业务文本格式，并建立 `HandoverSummaryVersion`。摘要必须关联明确的 `transcript_version_id`，防止转写被校订后摘要来源不明。

## 3.12 人工确认与删除规则

确认接口执行以下检查：

- 存在当前转写版本；
- 存在当前摘要版本；
- 用户位于记录的组织数据范围。

确认后 `business_status=confirmed`。已确认录音禁止通过删除接口处理；未确认录音采用 `deleted=true` 的逻辑删除并保留版本和审计。

## 3.13 注册 API

交接班模块提供：

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/v1/audio-records` | 创建音频和上传授权 |
| POST | `/api/v1/audio-records/{id}/uploads:complete` | 完成上传校验 |
| POST | `/api/v1/audio-records/{id}:transcribe` | 创建转写任务 |
| GET | `/api/v1/audio-records/{id}` | 查询主记录 |
| GET | `/api/v1/audio-records/{id}/segments` | 查询当前分段 |
| GET | `/api/v1/audio-records/{id}/versions` | 查询版本历史 |
| PUT | `/api/v1/audio-records/{id}/transcript` | 人工校订 |
| POST | `/api/v1/audio-records/{id}:summarize` | 创建摘要任务 |
| PUT | `/api/v1/audio-records/{id}/summary` | 人工修改摘要 |
| POST | `/api/v1/audio-records/{id}:confirm` | 确认交接班记录 |
| DELETE | `/api/v1/audio-records/{id}` | 受控删除 |
| POST | `/api/v1/manual-operation-records` | 创建人工运行记录 |
| PUT | `/api/v1/manual-operation-records/{record_id}` | 创建人工记录新版本 |
