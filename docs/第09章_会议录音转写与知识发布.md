# 第9章 会议录音转写与知识发布

[文档导航](README.md) · [上一章：知识与RAG](第08章_企业知识与RAG模块开发.md) · [下一章：隐患排查治理](第10章_隐患排查治理模块开发.md)

## 9.1 功能定位

`meeting`是独立业务模块，处理企业会议录音、参会人、版本化转写和显式知识发布。它复用StorageProvider、ASR Provider、AsyncJob、Outbox、权限和知识入库能力，但不复用交接班的班次语义，也不直接操作ES、Qdrant或Neo4j。

```text
创建会议与上传授权 → 上传录音 → 服务端校验 → ASR 转写
→ 人工校订说话人与正文 → 发布为 Markdown 知识版本
→ RAG 入库 → 知识审核 → 知识发布 → 普通读者可检索
```

“发布到知识”只表示会议侧内容冻结并送入知识治理。索引完成后的知识版本状态为`review`，必须由知识审核员审核并发布；未经审核内容不会进入普通RAG可见范围。

## 9.2 模块和数据

实现位于 [app/modules/meeting](../app/modules/meeting)：

| 实体 | 职责 |
|---|---|
| Meeting | 会议时间、组织、录音对象、ACL、当前转写与状态 |
| MeetingParticipant | participant_key、显示名、系统用户及会议角色 |
| MeetingTranscriptVersion | ASR或人工校订形成的不可覆盖版本 |
| MeetingTranscriptSegment | 起止毫秒、文本、说话人标签和置信度 |
| MeetingKnowledgePublication | 转写版本与知识文档、知识版本、索引Job的映射 |
| MeetingMinutesVersion | 与逐字稿版本绑定的AI纪要草稿、人工修订和确认版本 |

会议、知识发布、录音治理和纪要的表结构包含在[初始迁移](../alembic/versions/20260926_0001_initial_schema.py)中。权限包括`meeting:read/create/edit/process/publish`，内置`meeting_editor`角色同时具备所需知识编辑、上传和索引权限。生产授权仍应按职责拆分。

## 9.3 上传、转写与人工校订

会议使用两阶段上传：客户端先取得限时授权，上传后调用complete；服务端核对对象大小、MIME和可用摘要。对象键由后端生成，文件名不能成为任意路径。

转写任务类型为`meeting_transcription`，任务名为`app.modules.meeting.transcribe`，进入`audio`队列。Worker执行时重新恢复请求者及`meeting:process`权限。ASR输出保留分段时间、speaker_label、置信度和完整正文。

speaker_label是ASR临时标签，不是声纹确认的自然人身份。创建会议时可用participant_key建立参会人表，人工校订版本再把分段标签绑定到这些键。当前没有声纹识别和自动实名。

人工修改创建新的转写版本与全套分段，不覆盖ASR历史。分段必须有序且不重叠；已知录音时长时不得越界。会议发布后转写被冻结，避免知识来源被静默改变。

## 9.4 权限与知识发布

会议读取同时检查业务权限、组织范围和reader_ids。创建者与全局管理员具有相应访问能力。当前reader_ids在创建时固定，尚未提供带`expected_version`的会议ACL更新接口。

会议ACL与知识ACL是两套治理。发布适配器不会自动复制会议reader_ids到知识文档；目标知识库的ACL决定审核发布后的读者。发布前必须确认目标库不会扩大敏感会议内容的暴露面。

发布时生成包含标题、时间、地点、参会人和逐段时间范围的Markdown，例如：

```text
[32.180s–33.050s] 张调度：该事项暂不形成决议，下周复核。
```

文件通过正常KnowledgeDocument/KnowledgeVersion、对象存储校验和`knowledge_index`流程处理。文档代码为稳定的`MEETING-{meeting_id}`；同一转写版本只能准备一次，新转写版本可形成同一知识文档的新版本。

当前知识文档类型使用`handover`，从而采用叙事材料的意图边界分段。时间标记保留在Markdown正文，但Chunk locator还没有独立音频起止字段，因此前端暂时不能只凭证据ID精确回听原音频。

## 9.5 API

以下省略`/api/v1`：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST / GET | `/meetings` | 创建和列表查询 |
| GET | `/meetings/{meeting_id}` | 会议及参会人详情 |
| POST | `/meetings/{meeting_id}/uploads:complete` | 完成上传校验 |
| POST | `/meetings/{meeting_id}:transcribe` | 创建转写任务 |
| GET | `/meetings/{meeting_id}/transcript` | 当前转写与分段 |
| PUT | `/meetings/{meeting_id}/transcript` | 创建人工校订版本 |
| POST | `/meetings/{meeting_id}:generate-minutes` | 生成纪要草稿 |
| GET | `/meetings/{meeting_id}/minutes` | 读取纪要版本 |
| PUT | `/meetings/{meeting_id}/minutes` | 修改纪要 |
| POST | `/meetings/{meeting_id}/minutes:confirm` | 确认纪要 |
| DELETE | `/meetings/{meeting_id}/recording` | 删除录音对象并记录原因 |
| POST | `/meetings/{meeting_id}:publish-to-knowledge` | 生成知识版本并启动索引 |

发布接口要求会议发布权限，以及知识编辑、上传和索引权限；知识模块必须启用。响应包含publication_id、knowledge_document_id、knowledge_version_id和index_job_id。索引结束进入review，之后使用第8章审核与发布接口。

## 9.6 验证与当前边界

先配置可丢弃的独立`TEST_DATABASE_URL`，测试夹具会重建`public` schema：

```bash
uv run pytest tests/test_meeting_flow.py -q
```

`tests/test_meeting_flow.py`覆盖上传、ASR、人工版本、重叠分段拒绝以及知识review状态；`tests/test_delivery_gaps.py`覆盖纪要、录音保留期、显式删除及知识撤回后的状态同步。上线前还需用真实长录音验证多说话人、噪声、方言、超时、任务重投和人工校订体验。

纪要草稿固定来源逐字稿版本，人工修改后确认。未确认的AI草稿不是正式决议。知识版本撤回后，若会议没有其他未撤回的知识发布，会议状态同步为`withdrawn`。

录音支持带原因的显式删除（`DELETE /meetings/{id}/recording`）。`MEETING_RECORDING_RETENTION_DAYS`可配置自动保留天数；默认空值，禁用自动删除。定时任务只尝试删除到期且没有进行中处理任务、没有未撤回知识关联的录音。删除采用`deleting`到`deleted`状态，失败后可重试；逐字稿和纪要继续保留。当前仍未实现会议ACL修改、引用点击精确回听和声纹实名认证。
