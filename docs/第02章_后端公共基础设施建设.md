# 第 2 章 后端公共基础设施建设

## 2.1 本章目标

本章一次性完成五个业务模块共同依赖的基础设施。完成顺序固定为：

1. 配置对象；
2. 异步数据库；
3. Alembic 迁移；
4. 统一数据类型与公共模型；
5. 错误处理和请求上下文；
6. JWT、OIDC 和 RBAC；
7. 任务、审计与 Outbox；
8. 文字、语音、视觉和存储端口；
9. 默认 Provider 实现；
10. Celery、RabbitMQ 和 Redis；
11. FastAPI 装配；
12. Docker Compose 与基础测试。

基础设施只提供稳定能力，不包含交接班、事件、工单、巡检或报告的具体业务规则。

## 2.2 理解端口与适配器

业务模块不应直接依赖千问、OpenAI、faster-whisper、MiniCPM-V、磁盘目录或 AWS SDK。否则切换实现时，五个模块都要修改。

本项目把外部能力拆成四个端口：

| 端口 | 业务含义 | 默认实现 |
|---|---|---|
| `TextLLMProvider` | 结构化文字生成 | 远程千问 |
| `SpeechToTextProvider` | 音频转写 | 本地 faster-whisper HTTP 服务 |
| `VisionProvider` | 巡检图片候选识别 | 本地 MiniCPM-V HTTP 服务 |
| `StorageProvider` | 文件上传、读取、下载和删除 | 本地私有文件系统 |

未来接入 OpenAI、自训练模型或 AWS S3 时，只增加或切换适配器，业务 Service 的方法签名不变。

## 2.4 建立异步数据库层

创建 `app/shared/db.py`：

```python
from collections.abc import AsyncIterator

from sqlalchemy.ext.asyncio import (
    AsyncSession,
    async_sessionmaker,
    create_async_engine,
)
from sqlalchemy.orm import DeclarativeBase


class Base(DeclarativeBase):
    pass


class Database:
    def __init__(self, database_url: str) -> None:
        self.engine = create_async_engine(
            database_url,
            pool_pre_ping=True,
        )
        self.session_factory = async_sessionmaker(
            self.engine,
            expire_on_commit=False,
            class_=AsyncSession,
        )

    async def session(self) -> AsyncIterator[AsyncSession]:
        async with self.session_factory() as session:
            yield session

    async def dispose(self) -> None:
        await self.engine.dispose()
```

异步数据库的主要价值是：等待 PostgreSQL 时不阻塞 FastAPI 事件循环。`expire_on_commit=False` 允许接口在提交事务后继续序列化已经加载的对象。

创建 `app/shared/model_mixins.py`：

```python
from datetime import UTC, datetime
```

## 2.6 建立统一错误模型

创建 `app/shared/errors.py`：

```python
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse


class AppError(Exception):
    def __init__(self, code: str, message: str, status_code: int, **details) -> None:
        self.code = code
        self.message = message
        self.status_code = status_code
        self.details = details


class NotFoundError(AppError):
    def __init__(self, resource: str, resource_id) -> None:
        super().__init__("NOT_FOUND", f"{resource} not found", 404, resource_id=str(resource_id))


class ConflictError(AppError):
    def __init__(self, message: str, **details) -> None:
        super().__init__("CONFLICT", message, 409, **details)


def install_error_handlers(app: FastAPI) -> None:
    @app.exception_handler(AppError)
    async def handle_app_error(request: Request, exc: AppError) -> JSONResponse:
        return JSONResponse(
            status_code=exc.status_code,
            content={
                "error": {
                    "code": exc.code,
                    "message": exc.message,
                    "details": exc.details,
                    "request_id": getattr(request.state, "request_id", None),
                }
            },
        )
```

错误码用于前端稳定处理，HTTP 状态码用于协议层表达，`request_id` 用于串联接口日志、任务日志和审计记录。

## 2.7 建立 JWT、OIDC 与 RBAC

认证负责回答“用户是谁”，权限负责回答“用户能做什么”，数据范围负责回答“用户能操作哪个组织的数据”。三者必须分别校验。

创建 `app/shared/auth/schemas.py`：

```python
from uuid import UUID

from pydantic import BaseModel, Field


class CurrentUser(BaseModel):
    user_id: UUID
    subject: str
    username: str
    display_name: str
    organization_unit_id: UUID
    roles: set[str] = Field(default_factory=set)
    permissions: set[str] = Field(default_factory=set)
    organization_scope: set[UUID] = Field(default_factory=set)

    def can_access(self, organization_unit_id: UUID) -> bool:
        return "*" in self.permissions or organization_unit_id in self.organization_scope
```

创建 `app/shared/auth/dependencies.py`，完成以下处理：

1. 从 `Authorization: Bearer ...` 读取令牌；
2. 通过外部 IdP 的 JWKS 验证 RS256 或 ES256；
3. 校验 `iss`、`aud`、`exp`；
4. 使用 `iss + sub` 查询数据库用户、角色、权限和数据范围；
5. 提供 `require_permission()` 和 `require_data_scope()`。

权限依赖的核心形式：

```python
def require_permission(permission: str):
    async def dependency(user: CurrentUserDep) -> CurrentUser:
        if "*" not in user.permissions and permission not in user.permissions:
            raise PermissionDeniedError(permission)
        return user

    return dependency


def require_data_scope(user: CurrentUser, organization_unit_id: UUID) -> None:
    if not user.can_access(organization_unit_id):
        raise PermissionDeniedError("data_scope")
```

主后端不签发令牌，也不保存 JWT 私钥或共享密钥。本地开发令牌由独立 Mock IdP 签发；生产环境必须使用企业身份平台。

## 2.8 建立平台公共模型

在 `app/shared/platform/models.py` 中建立以下公共表：

| 表 | 作用 |
|---|---|
| `organization_units` | 组织层级和数据范围 |
| `user_accounts` | 用户映射 |
| `role_definitions`、`role_assignments` | RBAC 与数据授权 |
| `upload_sessions` | 两阶段上传及完整性校验 |
| `idempotency_records` | 请求幂等 |
| `prompt_template_versions` | 提示词版本 |
| `model_aliases` | Provider 与模型别名 |
| `business_config_versions` | 业务配置版本 |
| `ai_jobs`、`job_events` | 后台任务和进度事件 |
| `ai_call_logs` | 模型调用审计 |
| `workflow_runs` | 人工审核流程状态 |
| `audit_logs` | 业务审计 |
| `task_outbox` | 数据库事务与消息发布之间的可靠衔接 |

任务状态统一为：

```text
queued -> running -> succeeded
                  -> failed
                  -> cancelled
```

`config_snapshot` 保存任务创建时的 provider、model 和 prompt version。即使系统以后切换模型，历史结果仍能追溯到当时配置。

Outbox 的核心原则是：业务记录、AI Job 和待发布消息在同一数据库事务内提交；独立发布任务再把消息发送到 RabbitMQ。这样可以避免“数据库已提交，但 Celery 消息丢失”的窗口。

## 2.10 实现默认千问文字适配器

创建 `app/infrastructure/providers/qwen_text.py`。适配器调用百炼 OpenAI 兼容接口，并使用 Pydantic 输出模型生成 JSON Schema：

```python
class QwenTextLLMProvider:
    name = "qwen"

    async def generate_structured(
        self,
        *,
        operation: str,
        system_prompt: str,
        user_prompt: str,
        response_model: type[T],
    ) -> T:
        payload = {
            "model": self.model,
            "messages": [
                {"role": "system", "content": system_prompt},
                {"role": "user", "content": user_prompt},
            ],
            "response_format": {
                "type": "json_schema",
                "json_schema": {
                    "name": operation,
                    "strict": True,
                    "schema": response_model.model_json_schema(),
                },
            },
            "thinking": {"type": "disabled"},
        }
        response = await self.client.post("/chat/completions", json=payload)
        response.raise_for_status()
        content = response.json()["choices"][0]["message"]["content"]
        return response_model.model_validate_json(content)
```

严格结构化输出用于拒绝字段缺失、额外字段和非法类型。业务层不把自由文本直接写入事件、工单或隐患表。

同时建立：

- `HTTPASRProvider`：将存储中的音频临时物化并上传到本地 ASR 服务；
- `HTTPVisionProvider`：将图片上传到本地视觉服务；
- `OpenAITextLLMProvider` 与 `OpenAISpeechToTextProvider`：后期切换远程服务；
- `OpenAICompatibleTextLLMProvider`：接入自训练文字模型；
- 三个 Fake Provider：测试时返回确定性结果。

## 2.11 实现本地文件存储

`LocalFilesystemStorageProvider` 完成以下职责：

1. 生成带到期时间、大小、MIME 和 HMAC 签名的 PUT 地址；
2. 以流式方式接收文件，避免一次性读入内存；
3. 校验签名、有效期、对象键、声明大小和实际大小；
4. 计算 SHA-256；
5. 使用临时文件和原子替换完成落盘；
6. 生成短期下载地址；
7. 阻止 `..`、绝对路径和编码后的路径穿越。

对象键示例：

```text
audio-records/{audio_id}/{safe_filename}
inspections/{inspection_id}/{image_id}/{safe_filename}
work-orders/{order_id}/{attachment_id}/{safe_filename}
reports/{report_id}/{export_id}.docx
```

本地存储只是默认适配器。`S3StorageProvider` 使用相同端口，部署到 AWS 时可以通过 boto3 默认凭证链读取 ECS、EC2 或 EKS 的 IAM Role。

```python
from dataclasses import dataclass
```

## 2.13 建立 Celery

创建 `app/bootstrap/celery_app.py`：

```python
from celery import Celery
from celery.schedules import crontab

from app.bootstrap.config import get_settings

settings = get_settings()

celery_app = Celery(
    "pipeline_operations",
    broker=settings.celery_broker_url,
    backend=settings.celery_result_backend,
    include=[
        "app.modules.handover.application.tasks",
        "app.modules.operation_event.application.tasks",
        "app.modules.maintenance_order.application.tasks",
        "app.modules.inspection.application.tasks",
        "app.modules.report.application.tasks",
        "app.shared.platform.tasks",
    ],
)

celery_app.conf.update(
    task_acks_late=True,
    task_reject_on_worker_lost=True,
    worker_prefetch_multiplier=1,
    broker_connection_retry_on_startup=True,
    task_publish_retry=True,
    task_track_started=True,
    timezone="UTC",
    enable_utc=True,
    beat_schedule={
        "publish-task-outbox": {
            "task": "app.shared.platform.publish_outbox",
            "schedule": 1.0,
        },
        "generate-daily-operation-reports": {
            "task": "app.modules.report.generate_daily_reports",
            "schedule": crontab(hour=16, minute=10),
        },
    },
)
```

`acks_late` 和 `task_reject_on_worker_lost` 支持 Worker 异常退出后的重新投递。业务任务必须具备幂等性，不能把“可能重复执行”误认为“只执行一次”。

## 2.14 装配 FastAPI

`create_app()` 的生命周期按以下顺序执行：

```text
读取 Settings
    -> 创建 Database
    -> 创建 ProviderBundle
    -> 注册异常处理和 CORS
    -> 注册 request_id 中间件
    -> 注册健康、认证、任务、管理、存储和业务路由
    -> 关闭 Provider 客户端
    -> 释放数据库连接池
```

请求上下文中间件：

```python
@app.middleware("http")
async def request_context(request: Request, call_next):
    request.state.request_id = request.headers.get("X-Request-ID") or str(uuid4())
    response = await call_next(request)
    response.headers["X-Request-ID"] = request.state.request_id
    return response
```

就绪检查必须实际执行 `SELECT 1`；存活检查只表示进程仍能响应。
